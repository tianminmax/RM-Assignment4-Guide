# 交互式版本（Jupyter Notebook）

三个 notebook 是教程的"动手版"：把原来需要自己敲的命令、需要自己看的数据，都做成了可以直接运行的单元。
文字讲解仍在 `../*.md` 里，notebook 负责让你边跑边看结果。

| Notebook | 对应章节 | 你会完成什么 |
|---|---|---|
| [01-环境与数据](01-环境与数据.ipynb) | 02 环境搭建、03 数据准备 | 环境自检、跑通一次推理、把标签画出来核对、划分 train/val/test |
| [02-训练与评估](02-训练与评估.ipynb) | 04 训练入门、05 看懂指标 | 冒烟测试、baseline 训练、读曲线、评估拿到 mAP50/mAP75、误差分析 |
| [03-调参与交付](03-调参与交付.ipynb) | 06 调参方法、07 排错手册、08 进阶与交付 | 分辨率实验、三组对比、未标注数据、自动生成训练表格、打包与交付自检 |

## 用之前：把内核配好

Notebook 必须用**装了 torch 和 ultralytics 的那个环境**（教程里叫 `ai-env`）来跑，否则第一格就会提示缺依赖。

```bash
conda activate ai-env
pip install ipykernel matplotlib
python -m ipykernel install --user --name ai-env --display-name "Python (ai-env)"

jupyter notebook          # 或 jupyter lab / VS Code 里打开 .ipynb
```

打开后在右上角把内核切成 **Python (ai-env)**，然后从第一格开始按 `Shift+Enter` 往下跑。

> 用 VS Code 的话，打开 `.ipynb` 后点右上角选择内核，选 `ai-env` 即可。

## 三个设计上的取舍

**1. 训练用脚本调用，不写成内联 cell。**
一次 baseline 训练要 30~60 分钟。如果在 notebook 里直接 `model.train()`，内核会一直占着内存、进度条也会刷爆输出。
所以 notebook 通过 `run(script("train.py"), ...)` 调用配套脚本：脚本崩了不影响内核，长任务随时可以中断续训。
想学内联写法的话，notebook 02 的第 7 节有对照示例。

**2. 脚本位置自动查找。**
配套脚本可能放在 `<作业根>/code/`，也可能直接放在作业根目录，notebook 里的 `script()` 会把这两种情况都试一遍，
找不到时还会告诉你去哪找。这样你不用为了跑 notebook 去改目录结构。

**3. 图片直接显示在单元格下面。**
标签核对图（把标注框画在图上）、训练曲线、PR 曲线、混淆矩阵、漏检样本对比，都是 `show("路径")` 一行就显示——
这是 notebook 相比命令行最大的好处：**标注对不对，看一眼就知道**。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 第一格提示缺少依赖 | 内核选错了（选到了没装 torch 的环境） | 按上面的命令注册 ai-env 内核并切换 |
| 提示"找不到 train.py" | 配套脚本不在作业根目录或 `code/` 下 | 把教程的 `code/` 目录复制到作业根目录（与 `data/` 同级） |
| 提示"文件不存在，先运行生成它的那一格" | 跳过了前面的训练/评估单元 | 按顺序补齐，或直接改成你已有的实验名 |
| 训练单元跑很久没反应 | 正常，一个 epoch 要几秒到几十秒 | 看终端输出的进度；也可以先去做别的，回来再看 |
| 内存越用越多 | 前一次训练的中间变量没释放 | 内核菜单里选"重启内核"，再从上往下跑 |

## 和 Markdown 版本的关系

两个版本内容一致，用途不同：

- **想快速通读、或者要打印**：看 `../README.md` 和各个 `.md` 章节
- **想边做边看结果**：用这里的 notebook

做完一个 notebook 后，建议回到对应的 `.md` 章节看一遍讲解——那里的原理说明更完整（比如损失函数的推导、mAP 家族的定义）。
